# Codex Chrome 插件实测：多标签并行后，AI 浏览器代理终于顺手了

![原文图片1](/images/localized/686bbaa88bebb602.png)

## 写在前面

浏览器代理最烦的，不是不会点网页，而是总得人盯着。Codex 这次把 Chrome 插件接进来后，终于更像一个能在后台自己跑流程的 agent：你继续用你的浏览器，它在独立标签页里干活。

对普通用户来说，这种变化不在“多了一个功能”，而在“少了很多打断”。

---

## 核心变化：从“点网页”变成“并行跑流程”

这次最关键的不是自动点击，而是**独立标签页 + 后台并行**。多个 agent 可以分开跑，用户自己照样查资料、回消息、做别的事，不会被来回切页打断。

可以把它理解成三点：

- 能在真实登录的 Chrome 里工作；
- 能跨多个标签页收集信息；
- 能把浏览、筛选、归纳、填表串成一条流程。


## 官方演示：重点不是“能上网”，而是能把事做完

几个场景已经把能力说明白了。

### 1. 抓论坛内容并整理成表

它能自动浏览 OpenAI 开发者社区论坛，抓取最近一周和 Codex 相关的帖子，整理主题、问题、情绪，再导出成结构化表格。


### 2. 跑完报销流程

它能从 Gmail 找报销邮件，对照本地 PDF 收据，匹配日期、金额、商户信息，最后填表、上传、提交。


### 3. 多个 agent 在不同标签页协同

官方还让四个 agent 分别进入四个标签页，做同一个在线画图任务，最后生成四幅不同的灯塔画作。重点不是画图，而是能并行、能各自保留上下文。


## 安装和调用都不复杂

Codex 里可以直接找到 Chrome 插件并安装。连接完成后，会出现一个被接管的标签页，说明插件正在运行。

调用方式也直接：可以用 `@Chrome`，也可以在输入框里用 `/Chrome` 找到插件，再把任务说清楚。

再加上 Chrome 的 CDP 连接，Codex 能接到我们已经登录好的浏览器里做事，省掉不少重新登录和授权步骤。

## 常见问题

### 1. 它和普通浏览器自动化有什么区别？

普通自动化更像脚本，Codex 更像能理解任务的 agent。

### 2. 真能后台并行吗？

能，但前提是任务和 subagents 要说清楚。

### 3. 适合做什么？

适合搜索、整理、跨站对比、报销预处理、内容准备。

### 4. 能不能直接发布？

技术上可以走到很后面，但最好停在发布前一步，由人确认。

### 5. 文件上传失败怎么办？

先检查 Chrome 扩展权限，尤其是 `allow access to file urls` 是否打开。
