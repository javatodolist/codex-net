# 不切终端也能跑 Claude Code：这个 IDEA 插件把 Codex 也一起塞进来了


## 写在前面
如果你平时在 JetBrains 系 IDE 里写代码，应该都经历过一种割裂：AI Agent 明明很好用，但很多能力还得切到终端里跑，来回跳上下文特别影响节奏。

这篇里讲的 CC GUI（Claude Code GUI）就是在解决这个问题：直接把 **Claude Code + Codex** 放进 IDEA 侧边栏，一个面板里完成对话、执行命令、管理会话和供应商配置。

重点不在“又一个插件”，而在工作流变化：你不需要离开 IDE，也能把 Agent 化能力接进日常开发。

CC GUI 这类工具的价值就在这里：把 Agent 能力放进 IDE 的主工作面板，减少环境切换成本，让上下文更完整地留在一个地方。

## CC GUI 到底能做什么
CC GUI 是 MIT 协议开源项目，目前公开信息里 GitHub Star 已达 2.6k+，并且可以直接在 IDEA 插件市场安装。

它的核心能力可以归纳为五块：

1. **双引擎支持**：Claude Code + OpenAI Codex，一个插件内切换；
2. **智能对话**：支持 @ 文件引用、图片发送、对话回退、提示词增强；
3. **Agent 命令**：内置 `/init`、`/review` 等斜杠命令，并支持 MCP 扩展；
4. **开发体验优化**：代码 DIFF、权限管理、文件跳转、主题切换、中英文自动；
5. **会话管理**：历史搜索、收藏、导出、供应商切换、使用统计。

## 上手流程（IDEA 内）
整个流程比较直：

### 1）安装插件
在 IDEA 插件市场里搜索 Claude，安装 CC GUI 即可。

### 2）补齐 SDK 依赖
首次打开插件后，在设置里找到 SDK 依赖，下载 Claude Code SDK 或 Codex SDK，后续也可以在这里更新版本。

### 3）配置供应商
在 CC GUI 面板右上角进入“供应商管理”，添加：

- 名称
- API Key
- 请求地址
- 映射模型 ID

配置完成后启用即可。文章示例里用的是百炼的 Coding Plan 路线。

### 4）开始跑任务
在对话窗里选择 Claude Code 或 Codex 即可开跑。常见起手是先执行 `/init`，让 Claude Code 理解当前项目并生成 `CLAUDE.md`。

后续可以直接让它先给出改造计划，再按规划模式推进。示例场景是把项目从 Vite 7 升到 Vite 8，先出 Markdown 方案，再进入具体改动。

最直观的好处有三个：

- **减少切换损耗**：不用在 IDE 和终端之间来回跳；

尤其是你已经习惯 JetBrains 的工程化体验时，这种“在原地接入 Agent”的方式通常比重建工具链更平滑。

## 常见问题

### Q1：CC GUI 是不是只能用 Claude？
A：不是。它支持 Claude Code 和 Codex 两套引擎，可以按任务切换。

### Q2：安装后为什么还不能直接用？
A：首次需要在插件设置里下载并配置对应 SDK（Claude Code SDK / Codex SDK），同时完成供应商参数配置。

### Q3：`/init` 的作用是什么？
A：它会先理解项目结构并生成 `CLAUDE.md`，方便后续任务在统一上下文里推进。

### Q4：这类插件适合什么人？
A：适合长期在 IDEA/JetBrains 生态里开发、希望减少终端切换但又要保留 Agent 深度能力的开发者。

### Q5：国内怎么更顺畅接入 Claude Code 这类能力？
A：核心是减少支付和网络折腾，国内用户可以通过 [Code80](https://code.ai80.vip/home) 更方便地接入。
